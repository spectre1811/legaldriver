### F4 — `hero-case-detail`: Navigation to case detail too slow (>7.5s) in dev mode

**Spec**: `hero-case-detail.spec.ts › open a seeded case → detail renders clean with its record + refresh`
**Severity**: medium · **Type**: perf
**Error**: `expect(page).toHaveURL(/.../) timed out (7500ms)`

**What broke**: After clicking `a[href^="/dashboard/cases/"]` on the cases list, the URL stays on `/dashboard/cases` for >7.5s. The screenshot confirms the detail page DID load (correctly shows "State v. Kiran Patel" with tabs and AI briefing) — but only after the assertion window closed.

**Root cause**: Dev mode (`npm run dev`) compiles each page on-demand. The `/dashboard/cases/[id]` route imports `unpdf` via `src/lib/docs/extract.ts → file-upload.ts → actions.ts → cases/[id]/page.tsx`. The `unpdf` module triggers a webpack "Critical dependency: Accessing import.meta directly is unsupported" warning on every compile, likely causing repeated recompilation or slower first-render. The webserver logs this warning on every request to any cases route.

**Repro**: Consistent failure in both isolated and full-suite runs.

**Suspected files**:
- `src/lib/docs/extract.ts` / `file-upload.ts` (unpdf import chain)
- `node_modules/unpdf/dist/index.mjs` (upstream `import.meta` usage)

**Fix options**:
1. (Immediate) Increase `expect.timeout` in `playwright.config.ts` from 7500ms to 15000ms or configure a per-spec timeout for the navigation assertion.
2. (Better) Lazy-import `unpdf` or use a dynamic import with webpack hint to prevent it from being bundled into the SSR path of the cases page.
3. Run E2E against a production build (`npm run build && npm start`) instead of dev server — this is the correct CI approach per `playwright.config.ts` comment.

### F5 — `hero-manual-add`: No redirect after manual case creation

**Spec**: `hero-manual-add.spec.ts › create a manual case, land on its page, then delete it`
**Severity**: high · **Type**: bug
**Error**: `expect(page).toHaveURL(/\/dashboard\/cases\/[0-9a-f-]{36}/) timed out`

**What broke**: After filling the manual add form and clicking "Create case", the URL stays on `/dashboard/cases`. The `createManualMatter` Server Action (`src/app/dashboard/cases/actions.ts:294`) returns `{ ok: true, matterId, message }` but never calls `redirect('/dashboard/cases/${matterId}')`. The user is left on the case list with no confirmation and no navigation to the new case.

**The spec expects**: redirect straight to `/dashboard/cases/<uuid>` (the new case detail page).

**Repro**: Consistent failure even in isolation.
```bash
DEMO_MODE=1 E2E_EMAIL=demo@lexdriver.test E2E_PASSWORD=demo-pass-1234 \
  npx playwright test hero-manual-add
```

**Screenshot**: `test-results/hero-manual-add-create-a-m-f430a--on-its-page-then-delete-it-authed/test-failed-1.png` — form is filled, "Create case" button is visible, but URL never changed.

**Suspected files**: `src/app/dashboard/cases/actions.ts:294` (`createManualMatter`), `src/app/dashboard/cases/page.tsx` (the form's `useFormState` handler after `ok: true`)

**Fix**: After successful creation, redirect to the new case: `import { redirect } from 'next/navigation'` then `redirect('/dashboard/cases/${matterId}')` at the end of `createManualMatter`. (Or if the action must return a result for the form state machine, add a `redirect` inside the form's success handler on the client.)
