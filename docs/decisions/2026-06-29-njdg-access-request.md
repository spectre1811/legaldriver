# NJDG / eCommittee — authorized data-access request (draft)

The compliant route to **live** case-status/cause-list data (which open data does NOT
provide) is **authorized access** to NJDG, not scraping. NJDG's Open API is gated to
government departments / institutional litigants today, but the eCommittee's Phase III
(2023–27) explicitly envisages open APIs for third-party application providers. The move:
ask, on record, and keep HITL as the interim. Precedent to cite: the Kerala High Court
**DigiCourt API** SOP (a court exposing a documented API to authorized integrators).

**Send to:** `ecommittee@aij.gov.in` (eCommittee, Supreme Court of India)
**Cc (Gujarat focus):** the Gujarat High Court Central Project Coordinator (CPC) —
`cpc-gj@aij.gov.in` (verify the exact CPC alias on the Gujarat HC site before sending).
**From:** a firm/role address; attach a one-pager on Legaldriver + intended use + safeguards.

## Email draft

**Subject:** Request for authorized access to NJDG / eCourts case-data APIs for a compliance-first legal-practice tool

Respected Sir/Madam,

I am writing on behalf of **Legaldriver**, a practice-management tool for advocates in India that helps them track their own matters, deadlines, and hearings, and reference judgments — with a strict, compliance-first design.

We currently build only on **openly licensed data** — the AWS Open Data "Indian High Court Judgments" and "Indian Supreme Court Judgments" datasets (CC-BY-4.0), which we attribute and treat as reference material with a "verify against the official record" disclaimer on every record. We deliberately do **not** scrape the eCourts portals or attempt to bypass their CAPTCHA, as that would violate the Terms of Use.

To serve advocates with accurate, **current** case status and cause-list information, we would like to request **authorized, programmatic access** to the relevant NJDG / eCourts data services, under any conditions the eCommittee considers appropriate (rate limits, audit, data-handling and retention obligations, restriction to a firm's own matters, DPDP-aligned consent for personal data, etc.). We are happy to:

- enter into a data-sharing agreement / MoU and abide by its usage and security terms;
- restrict usage to legitimate practice needs and implement access controls, encryption, audit logging, and provenance display;
- comply fully with the DPDP Act, 2023 for any personal data of parties/advocates.

If a direct programmatic channel is not available to a private entity at present, we would be grateful for guidance on the correct process — including whether access is possible via a partner institution (a bar council, law school, or institutional litigant), and the expected timeline for the **Phase III** open-API ecosystem for third-party application providers.

We would welcome the opportunity to share more about our safeguards and intended use. Thank you for your time and for the eCommittee's work in building India's digital judiciary.

Respectfully,
[Name], [Role], Legaldriver
[Email] · [Phone] · [Website]

## Notes
- This is a **request**, not a guarantee — NJDG access for private SaaS is currently restricted; set expectations accordingly.
- Keep **HITL capture + cause-list upload + the open CC-BY corpus** as the working compliant stack regardless of the outcome.
- If you'd rather pursue a **licensed reseller**, only engage one that can **contractually prove authorized sourcing** (an actual NJDG license / eCommittee MoU) — per the diligence appendix, the common vendors (eCourtsIndia etc.) cannot.
